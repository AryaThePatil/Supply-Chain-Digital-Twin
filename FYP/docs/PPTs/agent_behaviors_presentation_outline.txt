## Slide 4: Agent-Based Modeling Paradigm

**Why Agent-Based?**:

- **Decentralized Intelligence**: Each entity makes autonomous decisions
- **Emergent Behavior**: System-level patterns emerge from individual actions
- **Realistic**: Mimics real-world supply chain operations
- **Scalable**: Easy to add more agents without redesigning

**Key Characteristics**:
- Agents perceive their environment (weather, traffic, inventory)
- Agents act based on internal logic and external stimuli
- Agents interact through orders, deliveries, and shared resources
- No central controller—distributed decision-making

## Slide 5: Agent Type 1 - Warehouse Agent

**Role**: Central distribution hub managing inventory and fleet

**Responsibilities**:
1. **Inventory Management**
   - Store oranges in cold storage (6°C, 88% humidity)
   - Track batch-level Remaining Shelf Life (RSL)
   - Monitor spoilage and remove expired batches

2. **Order Processing**
   - Receive orders from retailers
   - Prioritize based on urgency and inventory levels
   - Allocate trucks to fulfill orders

3. **Fleet Management**
   - Manage heterogeneous truck fleet (small, medium, large)
   - Track truck availability and status
   - Optimize truck-order allocation

4. **Restocking**
   - Monitor inventory levels against reorder point
   - Trigger restocking when below threshold
   - Schedule supplier deliveries

**Key Metrics**:
- Current inventory (kg)
- Available trucks
- Pending orders
- Trucks in transit

## Slide 6: Agent Type 2 - Retailer Agent (Wholesaler)

**Role**: Wholesale distribution center serving restaurants, shops, hotels

**Responsibilities**:
1. **Demand Simulation**
   - Generate customer arrivals (Poisson process)
   - Time-varying demand (hour, day, month)
   - Weather-sensitive demand patterns

2. **Sales Processing**
   - Fulfill customer orders from inventory
   - Track successful sales and stockouts
   - Record lost sales due to insufficient stock

3. **Inventory Management**
   - (s,S) reorder policy (reorder when inventory ≤ s, order up to S)
   - Calculate dynamic reorder points based on demand forecast
   - Safety stock based on lead time and demand variability

4. **Order Placement**
   - Select best warehouse (distance + load balancing)
   - Place orders when inventory low
   - Track pending orders and ETAs

**Key Metrics**:
- Current inventory (kg)
- Service level (% customers served)
- Stockout count
- Total sales (kg)

## Slide 8: Warehouse Agent - Detailed Workflow

**Decision Logic Flow**:

1. **Update Phase (Every Time Step)**:
   - Update RSL for all inventory batches in cold storage
   - Remove spoiled batches (RSL ≤ 0)
   - Update all owned truck agents

2. **Order Processing**:
   - Check for new orders from retailers
   - If orders available AND trucks available:
     - Select highest priority order
     - Allocate best available truck (capacity match)
     - Load cargo and assign route

3. **Truck Lifecycle Management**:
   - **Loading**: Truck waits for loading time (6-4 min per ton)
   - **Departure**: Truck begins route to retailer
   - **Transit**: Warehouse tracks truck via telemetry
   - **Arrival**: Truck unloads at retailer (4-2 min per ton)
   - **Return**: Truck returns to warehouse, status → idle

4. **Restocking Check**:
   - If inventory ≤ reorder point:
     - Schedule restocking event
     - Supplier delivery after lead time (1 ± 0.3 days)

**Example Scenario**:
- Retailer R001 orders 500kg
- Warehouse WH001 has 3 idle trucks and 10,000kg inventory
- Allocates medium truck (3-ton capacity)
- Loading time: 5 min/ton × 0.5 tons = 2.5 minutes
- Truck departs → arrives → unloads → returns

## Slide 9: Retailer Agent - Detailed Workflow

**Decision Logic Flow**:

1. **Demand Generation (Every Time Step)**:
   - Calculate arrival rate multiplier:
     ```
     arrival_rate = base_rate × time_of_day × day_of_week × 
                    month × weather × temperature_effect
     ```
   - Generate customer arrivals (Poisson distribution)
   - For each customer: generate purchase quantity (Gaussian)

2. **Sales Processing**:
   - Check if inventory ≥ requested quantity
   - If YES: Sell → Update inventory → Log sale event
   - If NO: Stockout → Log lost sale → Increment stockout counter

3. **Inventory Check (Every 6 Hours)**:
   - Calculate reorder point `s` dynamically:
     ```
     s = (avg_demand × lead_time) + safety_stock
     safety_stock = z_score × σ_demand × √(lead_time + review_period)
     ```
   - If inventory ≤ `s` AND no pending order:
     - Calculate order quantity (Economic Order Quantity or fixed days)
     - Select warehouse (40% distance, 60% load balancing)
     - Place order

4. **Order Tracking**:
   - Monitor order status (pending → assigned → in_transit → delivered)
   - Receive delivery from warehouse truck
   - Update inventory with delivered quantity

**Example Demand Multipliers**:
- Monday 10 AM: 0.9 (day) × 1.0 (hour) = 0.9× base
- Saturday 6 PM: 1.4 (day) × 1.6 (hour) = 2.24× base
- Rainy day: ×0.85 (people stay home)
- Hot day (35°C): ×1.2 (more fresh produce demand)

## Slide 10: Truck Agent - Detailed Workflow

**Decision Logic Flow**:

1. **Assignment Phase**:
   - Warehouse assigns order to truck
   - **Loading status**: Wait for loading time
   - Calculate route (Dijkstra on OSM network)
   - Departure event published

2. **Transit Phase (Every Time Step)**:
   - Update movement along route segments
   - Calculate effective speed:
     ```
     speed = min(truck_max_speed, segment_speed) × 
             traffic_congestion × weather_factor × 
             (1 - fatigue_penalty)
     ```
   - Update fuel consumption (load + speed dependent):
     ```
     fuel_rate = base_consumption × load_factor × speed_factor
     ```
   - Update cargo RSL based on ambient temperature
   - Check for rerouting (if accident on route)

3. **Driver Management**:
   - Accumulate fatigue (minutes driven)
   - Trigger break after 5 hours driving
   - Break duration: 30 minutes (truck stops)
   - Trigger sleep after 10-hour shift

4. **Arrival Phase**:
   - Reach destination node → **Arrived status**
   - **Unloading status**: Wait for unloading time
   - Deliver cargo to retailer
   - Quality check: Reject if average RSL < 72 hours
   - Return to warehouse

5. **Fuel Checks**:
   - Continuous monitoring
   - If fuel < 20% → Trigger refueling
   - Refueling time: 15 minutes (40 L/min)

**Example Movement**:
- Truck on 50 km route, dry weather, light traffic
- Base speed: 50 km/h
- Traffic multiplier: 0.9 (10% congestion)
- Weather multiplier: 1.0 (clear)
- Fatigue penalty: 0.02 (2% slower after 2 hours)
- Effective speed: 50 × 0.9 × 1.0 × 0.98 = 44.1 km/h
- Trip time: 50 / 44.1 = 68 minutes

## Slide 11: Agent Interaction Patterns

**Order-Delivery Flow**:

```
1. RETAILER: Inventory drops below reorder point
   ↓
2. RETAILER: Places order → Selects warehouse dynamically
   ↓
3. WAREHOUSE: Receives order → Adds to queue
   ↓
4. WAREHOUSE: Allocates idle truck → Loads cargo
   ↓
5. TRUCK: Begins route to retailer
   ↓
6. TRUCK: Transits (updates position, fuel, cargo)
   ↓
7. TRUCK: Arrives → Unloads at retailer
   ↓
8. RETAILER: Receives delivery → Updates inventory
   ↓
9. TRUCK: Returns to warehouse → Status idle
```

**Warehouse Restocking Flow**:

```
1. WAREHOUSE: Inventory ≤ reorder point
   ↓
2. WAREHOUSE: Schedules restocking event
   ↓
3. SUPPLIER: (External) Delivers after lead time
   ↓
4. WAREHOUSE: Receives batches → Updates inventory
```

**Collision Scenarios** (Agent Coordination):
- Multiple retailers order from same warehouse
  - **Solution**: Priority queue (urgency-based)
  
- Truck on route encounters accident
  - **Solution**: Reroute in real-time
  
- Warehouse has orders but no trucks
  - **Solution**: Queue orders until truck available

## Slide 12: Environmental Models - Current Implementation

**Weather Model**:
- **Type**: Markov chain state machine
- **States**: Clear, Cloudy, Light Rain, Rain, Heavy Rain, Fog
- **Seasonal Logic**: Monsoon (Jun-Sep) → 80% rain probability
- **Diurnal Patterns**: Fog in winter mornings (4-8 AM)
- **Temperature**: Month and hour-dependent (13-42°C range)
- **Humidity**: Season and weather-dependent (20-95%)
- **Affects**: Traffic speed, demand, accident rates

**Traffic Model**:
- **Type**: Greenshields model (density-based)
- **Formula**: `speed = free_flow × (1 - density/jam_density)`
- **Time-of-Day**: Rush hours (7-9 AM, 5-7 PM) → 2× density
- **Weather Impact**: Rain → 15-30% slower, Fog → 25% slower
- **Accidents**: Probabilistic based on road type, weather, time

**Disruption Model**:
- **Accidents**: Location-specific, duration-dependent severity
- **Frequency**: 1-3 accidents/day (realistic for city scale)
- **Impact**: Blocks lanes → Increases congestion → Rerouting

## Slide 18: Condition-Based Data Matching

**Intelligent Correlation Strategy**:

**Problem**: Real-time traffic API costs $300/month (not free)

**Solution**: Use historical traffic + current weather matching

**Approach**:
1. **Tag historical traffic** data with weather conditions
   - Uber Movement 2016-2018 data
   - Match each record with historical weather from same date/time

2. **Current simulation step**:
   - Get real current weather: "Heavy rain, 25mm/hr"
   - Query: "Find traffic patterns during heavy rain"
   - Apply historical traffic pattern to current routes

3. **Fallback hierarchy**:
   ```
   Exact match (heavy rain) 
     ↓ No data?
   Similar condition (rain, 0.90 similarity)
     ↓ No data?
   Time-of-day baseline + weather adjustment
   ```

**Academic Rigor**: Based on real correlations, not hardcoded multipliers!
